# 商品与预约状态图初稿审查清单

依据：实验一 `requirements.md`（lab1-final）、`report.pdf`、`chat.txt` 的相关业务规则，以及当前 `UML/类图.puml` 中的两套状态枚举。此文件为设计审查材料，不是实验报告正文。

## 同名事件与联动结果

两张图均用下列事件名称；它们表示一次业务操作在两个对象上的投影，不是先改一张图、再异步改另一张图。

|---|---|---|---|
| 买家提交预约 | 已发布 → 已预约 | 创建为待卖家确认 | REQ-011、016、017、018 |
| 卖家确认预约 | 已预约 → 已确认 | 待卖家确认 → 已确认 | REQ-013、015 |
| 买家取消预约 | 已预约 → 已发布 | 待卖家确认 → 已取消 | REQ-012 |
| 卖家拒绝预约 | 已预约 → 已发布 | 待卖家确认 → 已拒绝 | REQ-013 |
| 预约到期处理 | 已预约 → 已发布 | 待卖家确认 → 已超时 | REQ-013 |

## 设计推断及对应需求编号

1. **事件命名统一。** 将需求中的“发起预约、确认、取消、拒绝、超时、完成、普通终止、违规处理”统一为上表名称；名称是本稿设计选择，业务规则来自 REQ-011～020。
2. **使用两个复合分组简化连线。** 商品图用“未完成商品”覆盖草稿、待审核、已发布、已预约、已确认、已下架；预约图用“有效预约”覆盖待卖家确认、已确认。分组不是数据库新增状态，叶状态严格沿用类图八项和七项枚举。组边界上的违规箭头适用于所有子状态。（REQ-008、015）
3. **完成后违规采用内部处理。** 已完成状态内写明违规事件及其动作，避免画成已完成→违规下架或已完成→已终止；不使用 UML 最终伪状态结束对象行为，以便保留事后审计事件。其他预约终态也保留记录，不画返回有效预约的箭头。（REQ-008、015、029）
4. **终止申请不增加商品/预约状态。** “参与者提交终止申请”“管理员驳回终止申请”只更新申请对象，商品与预约保持已确认，因此两张图均用内部处理表示。普通批准的 G2 条件包含待处理申请、管理员核实双方同意、保存双方意见与原因、预约仍已确认；若完成先提交，则关闭申请并拒绝之后的批准。违规终止不依赖普通申请及双方同意。（REQ-014、019、029）
5. **时间事件由系统执行。** 将到期检查命名为“预约到期处理”，`expiresAt = createdAt + 24小时`，按服务端时间判定；确认、拒绝要求 `now < expiresAt`，超时要求 `now >= expiresAt`。定时任务的频率与实现方式不在状态图中决定。精确边界沿用 REQ-013，但该需求已声明其来源是拟稿速查规则，尚无独立真实甲方确认，不能解释为本次新确认。
6. **取消未额外增加到期时间守卫。** 买家取消以“当前仍待卖家确认”为条件；若到期任务尚未提交，取消与超时按最先合法提交的变更竞争。本稿没有推断取消也必须在24小时内；若希望到期瞬间统一强制超时，需要另行确认。（REQ-012、013）
7. **违规覆盖所有未完成商品。** 包括草稿、待审核、普通已下架；这根据“未完成违规商品转违规下架”及 REQ-015 的状态规则展开。违规下架状态再次处置只追加记录并保持限制，图中要求新的依据和原因；该重复处置的具体准入条件为本稿推断，不代表同请求重放可重复产生处置记录。（REQ-008、015、018、022）
8. **解除违规限制先到普通已下架。** 该操作不会恢复公开与可预约，仍须卖家重新送审。解除前“确认可解除、记录原因”是为管理员操作补充的审计条件；需求没有给出更具体的解除审批标准。（REQ-006、007、008、022；INT-01-L022、INT-02-L006）
9. **将公共守卫集中于图例。** 所有用户操作均核对角色与资源归属；写入重新核对当前状态、版本。G1 集中表达非自购、已发布、无有效预约、商品版本和价格一致及请求幂等。超时任务使用系统身份和读取的当前版本，不要求客户端提供版本。图中箭头表示校验并成功提交后的结果，不表示点击即成功。（REQ-002、011、016、017、018、020）
10. **失败及幂等重放不画成业务转换。** 无效输入、越权、旧版本、非法状态均拒绝并留痕；同标识同内容返回首次处理结果及预约当前状态，同标识不同内容拒绝。商品重新可售后，使用旧标识也不能重新走创建箭头；原预约终态不能复活。（REQ-017、018、022、029）

## 重点核对结论

- 确认前的取消、拒绝、超时均恢复商品为已发布；必须仍对应待卖家确认预约，不能覆盖违规处置已提交的结果。
- 确认后的普通终止仅在 G2 成立时由管理员批准；商品为已下架，不立即复售。
- 违规处置同步终止待卖家确认或已确认预约；已完成交易状态完全保留，仅追加记录和隐藏商品。
- 完成与普通终止/违规处置竞争时，以合法提交结果重新判断：完成先提交则后续违规只追加记录；终止先提交则完成请求拒绝。
- 图中没有已确认后的单方取消、自动完成、已完成复售、终态预约重启或违规商品直接上架路径。
