# 校园集 · 提交预约 UI 原型

当前阶段：本地静态网页，等待用户检查；未导入 Figma、未提交 Git。

## 查看

可直接用浏览器打开 `index.html`，无需安装依赖、联网或构建。

或在实验二目录运行：

```bash
python3 -m http.server 8765 --bind 127.0.0.1 --directory UI
```

四个固定画面：

- http://127.0.0.1:8765/#detail — 商品详情，1680元，已发布。
- http://127.0.0.1:8765/#confirm — 预约确认弹窗。
- http://127.0.0.1:8765/#price — 价格从1680变成1780元，提示重新确认。
- http://127.0.0.1:8765/#unavailable — 已被他人预约，提供返回列表入口。

弹窗为模态窗口，需先关闭/取消，再使用顶部画面切换。顶部“提交结果”选择器仅属于原型控制区，可以模拟正常成功、价格变化或被他人预约。选择“价格变化”后：详情 → 预约 → 确认 → 价格变化 → 按现价重新确认 → 新的1780元确认窗口 → 再次确认。取消不提交。

返回列表进入最小模拟列表；“进入详情演示”会重置商品以便重复检查，不声称真实商品已释放。

## 范围与需求

- 模拟已登录普通买家；商品、昵称、时间、价格与交付地点都是示例。
- REQ-010：商品标题、描述、分类、图片、价格、交付地点；公开界面没有联系方式。
- REQ-011：预约前展示确认价格；提交成功后为待卖家确认，商品为已预约。
- REQ-018：旧价格失败不生成预约，不自动接受新价格；重新确认形成新动作。
- REQ-016、027：被他人预约时给出明确业务原因和可行下一步，不显示服务异常。
- REQ-028、030：没有在线支付或私聊按钮，没有真实联系方式；所有交易线下进行。
- 依据 `UML/提交预约序列图.puml` 的 UI 可见结果制作，不在产品界面暴露 requestId、指纹、数据库锁等实现细节。
- 仅使用静态 HTML/CSS/JavaScript 模拟交互，没有后端、真实交易、完整幂等记录或并发保障。页面状态刷新会重置。
- 价格变更画面假设商品修改后已经重新审核并发布，以演示旧页面价格失效；不表示修改可以绕过重新审核。

## 视觉与素材

暖白背景、深绿操作色、中文无衬线字体，8px为主要间距基准；卡片16px、按钮8px圆角。桌面详情使用图片/信息双栏，窄屏改为单栏；弹窗保留可聚焦按钮、取消及 Esc 关闭行为。

## 卖家侧原型（待用户审查）

### 必填校验演示：缺价格和图片

1. 打开 `http://127.0.0.1:8765/seller.html?capture=1#publish`，隐藏顶部模拟栏。若已有待审核商品，先点击“撤回并继续编辑”。
2. 标题填写“微单相机与定焦镜头”；描述填写“机身和镜头正常工作，有轻微使用痕迹，附电池、充电器及背带，可当面检查。”；分类选择“数码电子”；交付地点填写“仙林校区 · 图书馆东门”。清空价格，移除全部已有图片，确认图片计数为 0/5。
3. 点击“提交审核”：价格字段下显示“请填写价格”；图片字段下显示“提交审核须上传1–5张图片”；顶部显示“请修正标出的内容，再继续操作。”。标题和描述等内容保留，状态仍为“草稿”。保持当前页面即可捕获，建议 Frame 命名“发布商品－必填校验”。
4. 捕获完成后，不修改数据，点击“保存草稿”：错误提示清除，显示“草稿已保存到本机浏览器”及保存时间，状态仍为“草稿”。刷新后字段恢复，价格仍为空、图片仍为 0/5。刷新不会恢复未保存的错误提示，需再次点击“提交审核”才能重现校验画面。

现有校验和保存流程已支持此场景，不需要改变表单业务行为。规则检查确认相同数据提交时仅返回价格、图片错误，保存草稿时无校验错误；实际浏览器显示及 IndexedDB 落盘需在预览中验证。

- 发布商品：http://127.0.0.1:8765/seller.html#publish
- 处理预约：http://127.0.0.1:8765/seller.html#reservations

沿用现有 style.css，并增加 seller.css、seller.js、seller-rules.js。

发布页支持缺字段保存草稿，使用本机 IndexedDB 保存字段与图片，刷新后可恢复；存储失败明确提示，不声称已保存。已填写字段仍须合法。提交时按 REQ-003 校验标题≤100字、描述≤2000字、分类、正数且≤100000元的两位小数价格、交付地点与1–5张有效图片。成功后持久保存“待审核”并展示结果，不能直接公开；“撤回并继续编辑”恢复草稿（REQ-004）。顶部“填入商品示例”便于检查成功路径；该按钮不会直接保存或送审。

处理预约页使用价格快照1680元，示例创建于打开前22小时，截止于打开后2小时（创建后24小时，北京时间显示）。确认与拒绝均再次检查当前状态和实际当前时间；拒绝时必须输入非空原因。达到截止时刻时转“已超时”并关闭操作，包括弹窗已打开时的提交按钮。确认后预约/商品均“已确认”，拒绝或超时后商品恢复“已发布”（REQ-013、015、020）。顶部“模拟预约到期”“重置预约示例”可重复检查；处理结果为内存模拟，刷新会重置示例，不代表真实预约被恢复。

纯静态原型没有服务器鉴权、真实管理员审核、并发事务或实际通知投递。当前浏览器连接服务仍不可用，仅完成 JS 语法、表单规则及时间边界检查，待用户实际预览。未进行 Figma 捕获；待本次用户确认后再导入同一文件。后续捕获可加 `?capture=1` 隐藏原型控制栏。

## 管理员侧原型（待用户审查）

- 待审核列表：http://127.0.0.1:8765/admin.html#reviews
- 审核详情：http://127.0.0.1:8765/admin.html#review
- 违规下架：http://127.0.0.1:8765/admin.html#violation

沿用 style.css、seller.css，增加 admin.css、admin.js、admin-rules.js。

审核详情显示卖家信息、商品字段、示意图片与历史记录。通过须二次确认，商品由待审核变已发布；驳回须输入非空原因，商品退回草稿。历史记录追加保留，本次已处理后按钮关闭，列表移除对应待审核项。顶部“模拟卖家已撤回”可检验失效状态；事件处理时再次核对状态与版本，防止原型重复操作（REQ-005、018、022）。不支持代改商品字段。

违规处置先显示影响范围、关联预约与价格快照，必须填写非空违规原因。默认商品和预约均为已确认，处置后商品违规下架、有效预约已终止；也可切换待卖家确认、无有效预约及已完成交易示例。结果页展示前后状态、历史快照保留、日志、待发送通知及原因。已完成商品仅隐藏及追加违规记录，不终止已完成预约。结果页不再提供重复提交入口，管理员可只读查看已处置记录（REQ-008、015、020、022）。

全部是内存模拟，刷新重置；“重置示例”和情景选择仅用于原型演示，不代表真实业务记录可删除或恢复。通知状态为模拟的待发送，不声称实际发送。无后端权限控制、真实数据库事务或审核/违规写入。实际实现仍须服务端鉴权与并发状态复核。

已通过 JS 语法、审核/违规分支校验及本地 HTTP 返回检查。浏览器控制服务仍报不可用，尚待用户浏览器视觉审查。此阶段不进行 Figma 捕获。捕获时可添加 `?capture=1` 隐藏模拟栏。
